# Cross-platform audit: Paseo Rooms plugin (M1 code)

Date: 2026-10-29. Scope: product code in `index.server.ts`, `index.client.tsx`, `server/`, `client/`, `shared/`, plus `package.json` scripts and the dev tooling under `tools/` and `test/`. Requirement: architecture principle 10 in `research/rooms-architecture.md`.

Method: I read the code. I also read the Paseo 0.13.2 daemon source inside `/opt/Paseo/resources/app.asar` to check how the daemon parses its listen address, writes `paseo.pid` and resolves `PASEO_HOME`. I ran `npm run typecheck`, which passed. I ran no tests, no daemons and nothing on macOS, Windows, WSL, Docker or a mobile device. Every non-Linux statement is either a verified property of the code or my judgement about how an OS behaves. The findings table marks which is which.

Labels used below:
- **Verified**: read in this code or in the Paseo 0.13.2 sources, or shown by `npm run typecheck`.
- **Judgement**: expected OS or runtime behaviour that I did not test.

## 1. Summary

The client side is in good shape. `client/`, `shared/` and `index.client.tsx` import only React, React Native, zod, TanStack Query and the Paseo plugin packages. They use no `node:` modules, no `Buffer`, no crypto and no platform globals (verified by grep). Clients hold no room keys, so React Native crypto support is not needed for M1.

Several patterns that are often a problem are absent from daemon-side product code (verified by grep). There is no `/proc`, `/dev` or `/tmp`, no `process.getuid`, no signals, no `child_process`, no shell and no `startsWith` path-containment checks. The stored-agent slug in `tripwire.ts` already uses `path.win32.parse` to match Paseo's Windows-aware implementation.

The gaps are in the platform-specific parts that principle 10 says must sit behind per-OS backends:

1. **File protection is chmod only** (X-1, X-2). On Windows, `chmod` only toggles the read-only attribute, so private keys get whatever ACL the parent directory has (judgement). On every OS, nothing checks the protection at startup, and `ensurePrivateDir` repairs modes silently. On WSL drvfs mounts the chmod is a silent no-op (judgement). On a Docker volume owned by another uid it throws and stops the plugin from starting (judgement).
2. **The upstream connection to the owner's daemon ignores named pipes** (X-3). Paseo 0.13.2 accepts `\\.\pipe\…` listen addresses and records them verbatim in `paseo.pid` (verified). The plugin would turn such an address into `ws://\\.\pipe\…/ws`, so every lane would fail on a Windows daemon configured for a pipe.
3. **Durable writes are POSIX-shaped** (X-4, X-6). There is no retry for Windows `rename` failures (EPERM/EBUSY), a temporary file holding secrets is left behind after a failure, and `fsyncDir` swallows every error on every OS.
4. **The room agent guard pins `process.execPath`** (X-5). Install layouts where the binary path changes between runs or updates would make the tripwire refuse existing lanes (fail closed).
5. **Tooling is Linux-only** (X-10). The task allows this for now. It means no test has run on any other platform.

Counts: **2 high, 5 medium, 8 low** (15 findings).

The identity-v2 specs (`docs/specs/identity-v2/identity-model.md` 7.8 and 7.9, `grants-v2.md` 7.3) already specify most of the fixes: Windows DACL, the startup check, rename retry, and skipping the directory flush on Windows. None of that is implemented in M1 code. The fixes below follow those specs where they exist.

### Checked and not a problem in M1 product code (verified)

- **No `/proc`, `/dev` or `/tmp` in product code.** These appear only in `test/`. The unit tests use `os.tmpdir()`.
- **No `uid` or `gid` use.** There is no `process.getuid`, and no `HOME` or `USERPROFILE` read. `os.homedir()` is used only for `~` expansion (see X-8).
- **No signals, `child_process`, `shell: true`, `bash`, `which` or PATH parsing in product code.** The inert MCP command is spawned by the agent provider, not by the plugin (see X-5).
- **No path-containment checks.** The only `startsWith` calls on paths are in `paths.ts:9` (`~`) and `local-daemon.ts:133-134` (listen form). Path joins use `path.join`. File names containing ISO timestamps replace `:` (`event-log.ts:104`), and ids are hex, so file names are valid on Windows.
- **The stored agent slug matches Paseo.** `projectDirNameFromCwd` uses `path.win32.parse`, matching Paseo's Windows-aware implementation, and the lookup falls back to scanning all project directories.
- **Line endings and encodings at runtime.** The event log writes `\n` and splits on `\n`. `JSON.parse` tolerates a trailing `\r`, so a CRLF-edited log still parses. All file I/O is UTF-8.
- **Crypto and network.** Server crypto is `node:crypto` Ed25519 and SHA-256, plus the pure-JS Noise in `@getpaseo/relay`, all available in Paseo's Electron Node 24 on every desktop OS. There is no client crypto. Relay connections are outbound WSS through `ws`, with no platform options.
- **Timers.** Long timers are capped at `2**31-1` ms (`member.ts:179`, `lane-endpoint.ts:595`).
- **Client code** uses `Platform.select` only for a font. It uses no regex lookbehind, `Intl` or `structuredClone`. Its only platform-dependent call is `copyText` from Paseo's own UI kit.

## 4. Recommended fix order

1. **X-2, then X-1.** Add the `FileProtection` interface with a POSIX backend and a startup check now, because it also closes a gap on Linux. Add the win32 DACL backend next, applied before the first key write. X-9 follows from this.
2. **X-4 and X-6.** Make `writePrivateFile` per-OS: exclusive-create temp file, temp cleanup, Windows rename retry, explicit directory-flush policy, and the documented weaker Windows guarantee. Add retry to `MemberRole.save`.
3. **X-3.** Parse the listen address with `@getpaseo/protocol`'s `parseHostTarget`, and support pipes and wildcard addresses. This is small and well-bounded.
4. **X-5.** Loosen the inert-MCP identity check to a stable form, and give a clear stale-lane message.
5. **X-13.** Settle native packaging (Q3) before any v2 key-storage work depends on it.
6. **Low items X-7, X-8, X-11, X-12, X-14, X-15.** These are cheap and can go in one change.
7. **X-10.** Port tooling when CI work starts, before release.

Until each item is fixed and run on the platform, `M1-RESULTS.md` should list macOS, Windows, WSL, Docker, web, iOS and Android as **untested**. Windows file protection and Windows named-pipe daemons should be listed as **not supported**.

## 5. Open questions
